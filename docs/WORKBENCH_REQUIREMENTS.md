# 机器学习小测平台：全站布局与学情诊断改造方案

请对当前机器学习小测平台进行一次完整的前端布局统一和学情诊断功能优化。

本次不是重新开发系统，也不是推倒重做现有界面。当前“我的任务”页面的整体布局、配色、卡片设计和信息密度已经比较符合要求，请将其作为全站视觉参考。

请先仔细检查项目现有代码、页面结构、组件、样式、接口和数据库，尽量复用现有实现，在保证功能正常的前提下完成改造。

## 一、全站布局统一（最高优先级）

### 1. 整个页面采用固定工作台布局

希望平台像桌面软件，而不是一张不断向下延伸的网页。

具体要求：

- 左侧导航栏固定。
- 页面顶部标题与核心操作区域固定。
- 页面主体根据剩余空间自动计算高度。
- 禁止浏览器主页面出现纵向滚动条。
- 内容较多的区域通过自身的滚动条展示。
- 表格、长列表、题目内容、诊断报告、资源列表分别在合理的容器内部滚动。
- 不允许因为设置 `overflow: hidden` 而将重要内容直接裁切掉。
- 不要靠缩小字号来解决空间不足。

技术实现建议：

- 应用根容器使用 `height: 100dvh`。
- 使用 Flexbox 或 CSS Grid 构建固定壳层。
- 正确设置 `min-height: 0`、`min-width: 0`，使子区域能够正常收缩。
- 页面主体使用 `overflow: hidden`，实际长内容容器使用 `overflow-y: auto`。
- 避免出现多个没有必要的嵌套滚动条。
- 使用统一布局组件，而不是每个页面分别实现一套固定高度方案。

以 1366×768 作为最重要的验收分辨率，同时兼顾 1280×720、1440×900 和 1920×1080。

对于更小的窗口或浏览器缩放，应保证所有重要操作仍然可达，不得出现内容永久无法查看的情况。

### 2. 统一顶部区域和统计卡片

参考现有“我的任务”页面。

当前“学习反馈”页面的顶部区域太高，试卷选择框独占一行，统计卡片也偏高，导致主体内容空间不足。

请进行以下修改：

- 优先把试卷选择框和“查看复测记录”等操作放到页面标题右侧。
- 如果当前窗口宽度不足，再采用紧凑的次级工具栏，不要强行挤压。
- 将统计卡片高度统一控制在约 80–90px。
- 将统计卡片适当收窄，参考“我的任务”页面的卡片比例。
- 四张卡片不必强行撑满整个屏幕，建议最大宽度约 250–270px。
- 缩小卡片内部不必要的上下留白，但保留正常字体大小。
- 统一图标大小、边框、圆角、阴影与卡片间距。
- 没有数据的统计项目不得虚构数值。

请尽量让统计卡片在第一屏更靠上，使下方主体内容拥有足够高度。

### 3. 全站统一设计语言

沿用当前系统的浅蓝色、白色和深蓝色文字。

整体风格应当清晰、干净，接近成熟的高校教学管理系统。

具体要求：

- 标题层级明确，正文舒适可读。
- 减少无意义的小标签、装饰性图标和颜色。
- 不使用大面积渐变、不必要的阴影和花哨动效。
- 不要把大量信息挤进过窄的卡片。
- 同一级别的标题和按钮在不同页面保持一致。
- 卡片和表格的间距、对齐方式、颜色规则统一。
- 避免同一功能在多个位置重复出现。

建议建立可以复用的页面壳层、统计卡片、内容面板、工具栏、空状态与滚动容器等基础组件。

## 二、学习反馈页面重构（重点任务）

当前页面的问题是：左侧错题展示和右侧 AI 学情报告同时出现，导致两边都受到空间限制，学情报告又过长，不容易阅读。

请采用“学情诊断 / 错题详情”双视图方案。

### 1. 顶部保持统一

页面顶部由以下内容组成：

- 页面标题及试卷选择工具栏。
- 本次成绩、错题数量、薄弱知识点、复测状态等核心指标。
- “学情诊断”和“错题详情”视图切换。

班级排名等已有信息可以保留，但如果没有真实排名数据，不要为了凑满四张卡片而展示没有意义的内容。

选择不同试卷时，成绩、诊断、错题和复测信息都必须同步切换。

### 2. 错题详情视图

保留现有两列错题卡片设计。

当前题干、选项、学生答案、正确答案、章节标签和参考解析等内容都比较直观，不需要大幅重做。

重点调整：

- 让两列错题卡片充分使用主体宽度。
- 将错题列表设置为独立滚动区域。
- 页面顶部标题、统计卡片和视图切换保持固定。
- 保留答案颜色标记，但不要出现过多重复标签。
- 参考解析支持展开和收起。
- 保证选项文字较长时仍能正常换行。
- 支持根据题号定位到对应错题。
- 切换视图时尽量保留当前试卷及相关选择状态。

### 3. 学情诊断视图

采用两栏结构：

左侧约 35%：诊断总览与知识点列表。

右侧约 65%：当前选中知识点的详细分析。

两侧根据内容需要分别滚动，不让整页滚动。

左侧展示：

- 本次诊断的简短结论。
- 薄弱知识点列表。
- 每个知识点对应的错题数、章节与学习优先级。
- 已经完成复测的知识点状态。
- 可以点击切换不同知识点。

右侧展示当前知识点的完整诊断，包括：

**A. 具体错误**

展示对应的错题题号、学生答案、正确答案、关键错误点。

例如第1题考查查准率，第2题考查召回率，如果学生在两题中互相选择了对方的公式，系统应指出这可能反映了两个指标的概念混淆。

不能仅仅复述“第1题选A，正确答案B”。

**B. 错因分析**

结合题干、选项、答案解析和知识点归类，分析学生可能存在的问题。

要求区分客观事实和推断：

- 客观事实：学生选了什么、正确答案是什么、对应什么知识点。
- 分析推断：学生可能混淆了哪些概念、缺少哪一步理解。

不能仅凭一道错题就断言学生完全不懂某个知识点。

对于没有足够证据判断错因的题目，明确表示需要通过专项复测进一步确认。

**C. 概念纠正**

用正常、易懂的语言解释正确知识点。

可以使用简洁公式、对比表格、具体实例，而不是堆砌 AI 生成的长段文字。

例如查准率与召回率，应直接展示二者的公式、含义和区别。

对于存在多个错误的知识点，尝试寻找共同的概念问题；如果没有共同原因，则分别说明。

**D. 学习资源**

将相应的课程资源直接放在该知识点的诊断详情下方。

展示：

- 课程资料名称。
- 对应章节。
- 真实定位到的 PDF 页码。
- 适合学生复习的具体内容。
- 打开对应课程资料的入口。

优先复用现有的资源索引及课程 PDF，不得编造不存在的文档与页码。

**E. 专项复测**

将复测功能与当前知识点直接关联。

如果当前系统允许学生自主生成或发起复测，就提供实际可用的操作；如果只能由教师发布，则显示真实的复测任务入口或等待教师布置的状态。

不能创建看似可以点击、但没有实际功能的复测按钮。

完成复测后，可以查看该知识点的复测成绩，以及与之前学习表现的比较。

## 三、重新设计 AI 学情诊断的内容生成逻辑

当前 AI 报告过于模板化，表现为：

- 大量重复“需要掌握某某知识点”。
- 简单复述学生选项和正确答案。
- 每个知识点安排几乎相同的学习时间。
- 诊断结果与具体题目之间的关联不够清楚。
- 资源推荐和学习建议彼此分离。

请不要仅仅把当前长报告拆成几张卡片，而是从生成逻辑上改进。

### 1. 先做结构化数据分析

由程序可靠计算：

- 实际得分与错题数量。
- 各知识点的错误分布。
- 每个知识点相关的题目数量及错误比例。
- 历史测验和复测表现（有数据时）。
- 知识点关联的教材资源。

注意不同知识点可能对应同一道题，不要重复统计后错误地声称错题总数增加。

如果题库中原有的知识点标签过于宽泛，优先在不破坏题库结构的前提下进行细化或补充，而不是把所有模型评估题都混在一个笼统的概念里。

### 2. AI 只负责适合它的部分

AI 负责：

- 结合真实题目解释可能的错误原因。
- 指出学生可能混淆的概念。
- 给出针对性的概念纠正方法。
- 根据当前问题组织合理的学习建议。
- 辅助生成专项复测题及解析。

不要让 AI 随意生成正确率、排名、错题数量、实验成绩、资源页码等客观数据。

对 AI 输出增加结构化格式和数据校验，确保每条诊断都能关联到真实题目。

不要把 AI 生成的长篇原始文字直接放进前端。

### 3. 学习建议必须具有可操作性

每个知识点的学习建议应回答：

- 我具体错在哪里？
- 需要理解哪个概念？
- 应该看哪份课程资料？
- 应该练习什么类型的题？
- 怎样判断自己已经掌握？

取消机械的统一“建议学习8分钟”等安排，除非系统有合理的学习时间估算依据。

尽量使用简短、自然的本科生能读懂的表达。

### 4. 诊断与复测必须形成真实闭环

目标流程：

学生完成测验 → 系统统计错误 → 生成针对性诊断 → 查看错因及课程资源 → 完成专项复测 → 更新学习记录。

对于复测数据，应正确关联学生、原测验、知识点和复测试卷。

明确区分“当前选择的试卷尚未复测”和“学生其他知识点此前已经复测达标”等不同范围，避免页面之间状态看似矛盾。

历史数据不足时，应明确显示数据不足，不能伪造学习进步趋势。

## 四、其他页面同步改造

### 1. 我的任务

保留当前良好的整体布局。

重点检查：

- 页面根容器不滚动。
- 顶部统计卡片固定。
- 待完成任务列表可局部滚动。
- 最近提交和考试记录分别局部滚动。
- 搜索、筛选和操作按钮保持可用。
- 两栏底部卡片高度协调，避免内容被裁切。

### 2. 学生答题页面

采用固定工作台模式：

- 考试标题、考试状态及必要的倒计时固定。
- 题目内容区域内部滚动。
- 题号导航和提交按钮保持容易访问。
- 题目数量较多时，不引起整个网页滚动。
- 不因固定布局而遮挡最后一题或提交按钮。
- 提交确认弹窗可正常显示、关闭和操作。

### 3. 在线学习资源

页面顶部保留搜索、筛选和资源分类。

资源列表内部滚动。

查看 PDF 时，文档阅读区域独立滚动，尽量支持按页码定位，并保留返回资源列表的操作。

### 4. 教师端其他页面

检查教师首页、题库管理、试卷管理、发布任务、成绩分析、AI 相关功能以及其他现有页面。

统一采用固定工作台式布局。

对于数据表格，优先使用表格内部滚动和固定表头。

对于需要填写很多字段的表单，可以采用内部滚动的抽屉或弹窗。

不要因为统一布局而改变现有教师业务逻辑。

### 5. 弹窗与抽屉

统一设置最大高度，超出部分内部滚动。

保证关闭按钮、保存按钮和取消按钮可见。

检查 Esc、焦点管理和键盘操作。

禁止弹窗出现后造成整个页面意外滚动。

## 五、技术实现和质量要求

1. 先检查现有布局体系，找出造成全页面滚动的根本原因。
2. 优先修复公共布局组件，避免逐页重复写固定高度代码。
3. 保留现有技术栈、路由、接口及数据库结构，除非确实需要必要调整。
4. 尽量复用原来的卡片、按钮、错题组件和课程资源组件。
5. 不为了追求代码简洁而删除已有正常功能。
6. 不使用模拟数据代替真实数据。
7. 不新增空按钮、假页面、占位报告或虚假的成功状态。
8. 不进行无关的大规模重构。
9. 如果涉及数据结构调整，应提供兼容方案与必要的迁移或测试。
10. 改动完成后必须运行项目进行真实验证。

## 六、验收标准

请至少完成以下验证。

**布局验收**

在 1366×768 分辨率下：

- 学生端和教师端主要页面没有浏览器整页纵向滚动。
- 左侧导航和顶部主要操作始终固定。
- 每个长列表、表格和报告都有可用的局部滚动。
- 主体内容不会溢出容器或被遮挡。
- 字体大小正常，无明显缩放塞内容的情况。

优先使用 Playwright 或现有浏览器自动化检查页面滚动高度、元素可见性、滚动容器行为，并保存关键截图。

同时检查 1280×720、1440×900 和 1920×1080 的布局表现。

**功能验收**

使用真实账号与真实数据验证：

- 学生选择试卷后能查看正确的成绩、错题和诊断。
- 学情诊断与错题详情能正常切换。
- 点击知识点后，右侧显示对应的真实题目依据。
- 点击题号能够找到相应错题。
- 资源入口能打开正确的课程资料。
- 复测状态与真实任务记录一致。
- 已有复测功能不因前端改动而失效。
- 复测完成后能够正确记录并显示更新结果。
- 教师端原有任务发布、题库和试卷功能正常。

**最终交付**

请直接完成代码修改和实际验证，不要只输出设计说明。

最后给我：

1. 修改过的页面和组件清单。
2. 核心布局改造说明。
3. 学情诊断逻辑修改说明。
4. 实际运行的功能测试结果。
5. 1366×768 下的主要页面截图。
6. 尚未解决的问题与原因。

最终目标是一个布局统一、功能真实、适合课堂展示和课程项目答辩的机器学习教学平台。

请特别注意：我追求的是清晰、舒适、实用，而不是华丽。不要让界面产生明显的 AI 模板感，也不要为了美观牺牲功能。
