# 班级知识点矩阵与自适应学习路径

本轮在原有班级统计、知识点地图、学习证据时间线和 LangGraph 复测流程上增加两个入口。无需数据库迁移，不覆盖历史试卷或答卷。

## 教师：从班级诊断进入分组训练

入口：学情诊断 → 多人单卷 → 选择考试 → 知识点矩阵。

矩阵以学生为行、登记知识点为列。统计固定在同一试卷版本，每名学生使用该版本的当前有效答卷；只按题项的主知识点计数，不把辅助标签重复累计。单元格同时显示原卷答对数量和结合关联复测证据的状态。零分、未评分、缺考、未交卷分别处理，原卷答对不直接等于知识点达标。

支持学生编号搜索、需加强优先排序、关注筛选、固定表头与首列、横向滚动。关注筛选包含需加强、待评分、缺考、未交卷和待完成复测。点击单元格可查看原卷关联题目及其评分状态、资料和完整答卷入口。矩阵不额外暴露学生真实姓名。

选择目标知识点和学生后，确认发布分组训练。服务端先校验整组选中学生的班级、提交状态、账号绑定和目标知识点评分，再逐人加入原有复测队列。训练使用已核验题库，不触发付费模型生成。每人依据各自学习证据选择阶段；已有活动任务直接继续，失败可重新发布恢复。发布结果逐人显示，部分失败不会伪装成全部成功。

接口：

| 方法与路径 | 用途 |
| --- | --- |
| GET `/api/teacher/class-matrix` | 固定班级及试卷版本的矩阵 |
| POST `/api/teacher/class-matrix/practice` | 传入 classroom_id、assessment_version_id、student_ids、kp_id，发布分组训练 |
| GET `/api/teacher/class-matrix/jobs/{job_id}` | 读取复测队列的最小进度和逐人结果 |

以上接口均要求教师身份。不能向未评分、未绑定学生账号或其他班级学生发布本组训练。

## 学生：按证据安排下一步

入口：我的任务 → 已完成原卷 → 学习反馈 → 选中知识点 → 学习路径。

路径将资料阅读、针对性训练、证据与延后确认放在同一面板。按钮直接打开对应资料、准备或继续实际答卷、查看证据时间线。已阅读状态来自真实学习活动记录，不参与评分。细分展示概念的训练范围仍按登记知识点整体证据计算，页面明确说明范围，避免页面阶段与实际组题依据不一致。

| 当前证据 | 训练阶段 | 优先难度与层次 |
| --- | --- | --- |
| 仍有可靠错答 | 基础巩固 | 基础、理解 |
| 证据不足 | 应用验证 | 中等、应用 |
| 已达标且尚未到延后检测时间，或已延后确认 | 迁移巩固 | 困难、应用 |
| 已达标且到达延后检测时间 | 延后确认 | 中等、应用 |

难度是选题偏好，不是保证。组题先保护未见题独立性、题族和考查角度，再按难度接近程度与认知层次选择。真实模型生成分支也接收阶段配置，不同阶段分别缓存候选池。题目最终仍经过原有校验。实际题源、难度、目标难度与阶段写入选题清单及试卷蓝图。

原有掌握度规则继续生效：至少两个独立题族、两个考查角度，有可靠评分且相关题全部答对，正式复测才可能达标；至少间隔24小时开始的新检测用于延后确认。重复题或不足的新题证据只能作为巩固练习，不能替代新题检测。已有活动任务优先继续，不因再次点击产生重复轮次。

实现位于 `class_matrix.py`、`adaptive_learning.py`、`learning_loop.py`、LangGraph 复测图，以及 `ClassKnowledgeMatrix.vue`、`AdaptiveLearningPath.vue`。

## 实测与证据

证据目录：`docs/acceptance/matrix-adaptive/`。

| 验证 | 实际结果与记录 |
| --- | --- |
| 完整后端回归 | 227项通过，`backend.txt` |
| 前端单元测试 | 47项通过，`frontend.txt` |
| 类型检查、生产构建 | 通过，`typecheck.txt`、`build.txt` |
| 新增确定性测试 | 身份与整组校验、版本口径、零分/未评分/缺考、阶段时间边界、独立题与难度偏好、主知识点路径对齐 |
| 真实浏览器 | 16人矩阵、搜索与关注筛选、原卷依据、两人训练发布、重复发布恢复、两种学习路径、打开实际答卷、390px手机布局及发布操作，`browser.json`及PNG |
| 数据库读回 | 每人仅一个轮次、阶段和选题元数据持久化、本轮新增模型调用为0，`readback.json` |

浏览器验收在隔离数据目录运行。通过实际接口发布两题原卷，STU001真实提交正确答案得10/10，STU002真实提交错误答案得0/10。前者显示“证据不足/应用验证”，后者显示“需加强/基础巩固”。没有直接改写数据库得分或诊断。

该演示知识点的未见题不足，实际准备的是两题巩固练习；原题没有登记难度，读回中的实际难度为空。页面和结果均保留练习属性，不声称完成正式新题检测。足量题库下基础阶段选基础题、迁移阶段选困难题的行为由自动测试验证。本轮未测试付费模型在线生成，生成参数接线已实现，使用时仍受模型可用性与审核结果限制。

## 复现与演示

在项目根目录准备新的隔离目录并启动：

```powershell
$env:MLQ_DATA_DIR = Join-Path $PWD 'data/matrix-demo-new'
$env:MLQ_MODEL_PROVIDER = ''
$env:MLQ_MODEL_API_KEY = ''
.\start.ps1 -NoBrowser -Port 8023
```

首次启动会恢复仓库匿名数据。关闭同端口旧实例后再启动；不要把这些命令用于正在展示的实例。需要停止时，保持相同的 `MLQ_DATA_DIR` 执行 `.\start.ps1 -Stop -Port 8023`。

可使用带 Playwright 的 Node 环境运行浏览器验收脚本。脚本会发布考试、提交两名演示学生的答案并发布训练，只应作用于隔离演示数据。默认生成新的验收目录；如要恢复同一次验收，设置相同的 `MLQ_ACCEPTANCE_OUTPUT`。

```powershell
$env:MLQ_ACCEPTANCE_ISOLATED = '1'
$env:MLQ_ACCEPTANCE_URL = 'http://127.0.0.1:8023'
# 若Playwright不在通常的模块搜索路径，设置RUNTIME_NODE_MODULES为其node_modules绝对路径。
node backend/scripts/verify_matrix_adaptive_browser.mjs
```

建议演示顺序：教师打开本次考试的矩阵 → 搜索并查看两名学生的依据 → 选中目标和学生发布训练 → 再次发布展示复用 → 分别切换两名学生查看阶段差异 → 打开训练答卷 → 查看原有证据时间线。准备足量经审核的独立新题后，可继续展示正式复测与掌握度更新；题库不足时按页面解释巩固练习边界。
