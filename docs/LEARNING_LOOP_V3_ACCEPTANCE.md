# 学习闭环 v3：实现与验收

2026-11-18 实施，2026-11-19 完成交付收尾；在 `fdcf405` 的工作区上实施。原始课程成绩、历史答卷和旧轮次保留；真实操作使用单独的 `data/loop-v3-acceptance` 数据目录，未覆盖正式数据。

## 改了什么

- 教师发布和学生自助共用 LangGraph 复测流程。每轮 5 题、最多两个知识点，两个目标按 3+2 分配；根据最新证据和覆盖次数轮转。
- AI 优先生成并独立验答；模型未配置、超时、答案不一致时，从可靠题库补足。题目不足、重复题、使用提示只计练习，保留尝试生成新题入口。
- 整轮通过、知识点达标、延后确认分开判断。新任务和待评分不撤销已有成果，可靠错答可以降为需加强，旧通过记录保留。
- 学生不能以教师身份发布，也不能访问其他学生的任务和答卷。跨角色重复请求按学生和原卷范围去重，发布前再次在数据库事务内检查。
- 修复“我的任务”中自主复测的空分发编号被误判为加载中、导致继续答题按钮禁用的问题。
- 学生反馈页和答卷结果页、教师三个诊断范围均保留复测操作区。通过结果、轮次和时间可见；任务进度与学习结果分别展示。
- 默认资料收敛为课程原页与一个相关外链；更多资料进入抽屉。原卷全对而复测答错的知识点，也会刷新推荐资料。
- 数据迁移只添加兼容字段与索引；历史轮次缺少独立性证据时不自动升级为知识点达标。

## 如何判定

| 层次 | 当前项目标准 |
|---|---|
| 本轮复测通过 | 正式 5 题全部可靠评分，至少 4 题答对 |
| 知识点达标 | 同轮该主知识点至少 2 道独立新题、不同题族和考查方式，全部答对 |
| 延后复测确认 | 达标至少 24 小时后开始另一组新题，再次满足达标条件 |
| 练习完成 | 重复题、提示、题量不足等不能升级为达标 |

程序负责规则判定，AI 负责出题和解释。规则集中于 `learning_evidence.py`，整轮阈值使用现有 `MLQ_TARGETED_RETEST_ACCURACY_THRESHOLD` 配置；改变标准时应同时更新规则版本和边界测试。这些短测结果不代表对长期掌握的绝对证明。

最终完整后端测试 213 项通过（72.69 秒）。前端 38 项通过；TypeScript 检查、Vite 生产构建通过。

测试覆盖：4/5 通过但知识点有错题、单题、待评分、重复题、提示、同题族、同考查方式、辅助标签、旧数据证据不足、24 小时边界、7 个知识点轮转、模型未配置/超时/验答失败、题库不足、无历史基线、双方去重、worker 中断恢复。浏览器演示成绩为验收输入，不是真实学生学习效果。

| 隔离账号 | 实际流程与结果 |
|---|---|
| STU001 | 打开诊断和课程原页→自主复测→5/5提交→两知识点达标。该轮为 3 道 AI 新题＋2 道题库题。随后发起第三轮练习，第二轮通过与知识点达标保留。 |
| STU002 | 打开诊断和课程原页→续做题库备用复测→刻意答错一道题→4/5整轮通过；偏差-方差达标，L1/L2需加强并有对应资料。再次点击复测后进入第三轮新题。 |

## 页面与链接

实际检查 1366×768、1280×720，以及 600×800 窄屏；核心结果和复测按钮保持可见。窄屏一次显示一个内容面板，通过按钮切换，长内容局部滚动；多卷的错题与考试记录每页 5 条。125% 的布局还使用 1024×576 的等效 CSS 视口检查；浏览器工具没有可靠报告实际缩放百分比，因此不把等效检查冒充精确缩放测量。

35 个课程知识点的 82 处原页引用均找到并核验图片。当前筛选后的 16 个外链 HTTP 检查均返回 200，但这只证明可访问。抖音复测推荐页在浏览器中出现登录遮挡层，已标为受限并从默认推荐移除；课程原页保持可用。其他外部平台仍可能要求登录，未逐条确认正文可读的链接不标为已核验内容。检查时间和可读状态保存在 `backend/app/data/resource_access.json`。

## 如何复现

```powershell
python backend/scripts/restore_acceptance.py --snapshot learning-loop-review --output data/loop-review
$env:MLQ_DATA_DIR=(Join-Path (Get-Location) 'data/loop-review')
python backend/scripts/bootstrap_demo.py
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8018
# 另开终端，设置同一个 MLQ_DATA_DIR 后启动 worker：
python -m backend.app.workers.worker --interval 2
# 登录信息由 bootstrap 在本机生成；随后只读复核：
python backend/scripts/verify_learning_loop.py --url http://127.0.0.1:8018
```

无模型配置也能使用题库备用路径。真实 AI 需要本机 `.env` 配置；交付包不包含密钥、密码哈希或登录会话。验收快照有意保留第三轮待完成任务，用于演示续做和历史成果保留。已将该快照恢复到一个新目录并通过 SQLite 完整性检查。

## 这次检查的方法

先沿“诊断→资料→复测→提交→评分→反馈→下一轮”追踪同一学生、同一原卷的数据，再构造容易遗漏的边界。原有测试通过，只说明旧断言成立；新增业务场景才能发现“新发布任务把以前的达标抹掉”等问题。

这里最关键的设计是把两类状态分开：`task_state` 回答“现在要做什么”，`concept_results` 回答“现有证据支持什么结论”。前端展示服务端结果，不另外猜学生是否学会；不同角色和报告范围因此使用同一套证据规则。
