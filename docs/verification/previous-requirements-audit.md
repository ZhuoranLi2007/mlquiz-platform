## 本轮修复

1. 班级诊断结果采用嵌套knowledge_point和chapter结构，原干预流程按平面字段读取，可能找不到真正弱点。现统一适配，并按目标知识点生成和验收。
2. 一份班级复测发布允许多名学生，原release_id唯一索引却只能保存一条复测周期。现改为release_id与student_id组合唯一，并迁移旧索引；历史行不删除。
3. 复测开始、交卷、任务列表均按当前学生关联周期，避免读到其他同学的原卷或结果。普通考试不错误执行复测检测。
4. 教师针对性复测接入已注册verify_learning，交卷后执行评分、前后对比和诊断更新。默认80%为“本轮达标”，不代表长期掌握；旧个人错题复测仍保留独立新题、全对与延迟复测规则。
5. 每轮目标知识点数量不超过题数，避免要求覆盖7个知识点却只生成5题；未覆盖弱点保留在结果中，后续轮次仍需检查。
6. 教师组卷和AI干预使用后台job与轮询；相同进行中的请求复用job，学生不能查询教师任务。worker需正常启动。
7. 保存真实模型messages与返回内容，关联调用ID及脱敏后请求摘要；新增教师端“导出运行提示词”。不把模型调用次数当成完整提示词记录。
8. 生成器遇到错误数组、答案类型、选项或引用时安全拒绝；同批题目也做去重，避免异常模型输出直接污染题库。
9. 打包4张原EMF公式的核对后PNG副本与哈希旁证，Linux读取原有题目不再依赖仅Windows可用的EMF渲染器。没有改写原始EMF及原题清单。
10. 修复交卷异常回退分支的未定义用户ID；资源推荐改为知识点ID精确匹配。

## 可重复验证

在项目根目录，安装依赖后执行：

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe backend/scripts/verify_course.py --output smoke-result.json
cd frontend
npm run test:unit
npm run typecheck
npm run build
```

verify_course.py 使用临时目录恢复快照，不打开本机正式数据库、不调用付费模型。它通过真实FastAPI端点执行功能，不模拟浏览器点击。AI集成回归放在 backend/tests/test_course_acceptance.py。

## 本地最后一轮验收

1. 解压到一个新目录，运行 start.ps1；保留原项目和data目录备份。旧数据更新时init_db自动新增提示词表并调整复测索引，不要用演示快照覆盖自己的数据库。
2. 在.env配置自己的模型参数，确认worker启动。教师选择一份确有错题的学生答卷，点击AI分析与复测，等待任务完成；检查新题、参考答案、引用和发布对象。
3. 用对应学生身份作答；回到教师端查看本轮达标与剩余错题。对一人多卷、班级多人一卷分别演示一次。班级内没有原卷有效答卷的学生无法进行原卷前后对比，不能编造基线。
4. 教师端导出真实运行提示词；补入指定开发平台的真实开发记录。不要上传.env、会话token或学生身份资料。
5. 报告与PPT补齐成员和课程信息；通过真实演示后，将本表的待验项目更新为实际结果。老师提供的原始xlsx/docx未包含在本包中，本次只能核查其保留的匿名记录和原题旁证，不能重新逐单元格核对原始附件。
